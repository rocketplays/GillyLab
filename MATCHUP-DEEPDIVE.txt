WHAT THE FEATURE IS
--------------------------------------------------------------------------------
A "Matchup Analytics ⌄" dropdown on every upcoming bout, beside "Fight Info". It
crosses one fighter's offence against the other's defence — the thing the existing
Fight Info dropdown structurally cannot do, because it only ever reads a fighter's
own numbers.

It renders counts, and a two-sentence read generated from the data:

    "Usman has 50 minutes of control time across those fights; Du Plessis has 16.
     Usman is far harder to take down: 27 of 32 stopped, against 8 of 23."

40 of 50 bouts get a read; 10 say nothing, which is correct — most fights are not
lopsided, and a panel that always has a verdict will invent one.


THE DATA, AND WHY IT'S IN THREE FILES
--------------------------------------------------------------------------------
    data/grid-names.json   2.2KB    eager     names + baselines; gates the button
    data/fight-grid.json   245KB    on click  the 3x3 strike cross-tab
    data/fight-stats.json  8MB      eager     UNCHANGED — not one byte added

index.html eager-fetches fight-stats.json on every page load. The grid would add
~2MB to that for a panel you have to click, so it lives apart and loads on press.
The manifest exists because the BUTTON'S VISIBILITY is decided while rendering
every bout — answering that from fight-grid.json would mean a 245KB fetch on page
load to decide the visibility of a button most people never press.

THE GRID IS THE POINT. ESPN serves head/body/leg BY distance/clinch/ground and the
backfill was summing it into margins and throwing the cross-tab away. Measured
across 63 card fighters:
    head accuracy AT DISTANCE    mean 35.8%  sd 4.9
    head accuracy ON THE GROUND  mean 70.2%  sd 8.2
    corr(the two)                -0.04
Zero correlation — unrelated skills. "Head 79%" reads identically for a boxer and
a ground-and-pounder. Mackenzie Dern is +55 points better on the ground than at
range; a kickboxer is +11. The margin reported one number for both.

TRAPS — ALL OF THESE WERE REAL BUGS TODAY
--------------------------------------------------------------------------------
  * THERE ARE TWO fightRow FUNCTIONS. renderHomeFightCard() draws the featured
    card; renderCarousel() draws the upcoming cards. Patching one put the button on
    one card and nowhere else, which reads as "the feature doesn't exist" — and did.
    Every change to a fight row is two changes. This is worth actually fixing.
  * NAME JOINS. Written wrong THREE times in one day: "Dricus Du Plessis" vs
    "Dricus du Plessis", "Aleksandar Rakic" vs "Rakić". Every lookup must normalise
    (NFD, strip diacritics, lowercase). A miss looks exactly like absent data.
  * `" " in name` DROPS MONONYMS. Sumudaerji, Aoriqileng — 10+ fights each, silently
    excluded. Read bouts[].fighters[].fighterName; don't hunt for keys called "name"
    and then filter the junk.
  * --only-missing CANNOT SEE THIS. Its predicate is "have we ever saved this
    fighter" and every card fighter is already saved — without the grid. Use
    --needs-grid, which asks the actual question and is self-clearing (no mark file).
  * split-fight-grid.cjs MUST MERGE. fight-grid.json is the ONLY copy of the grid;
    rebuilding it from scratch each run deletes everyone not in that batch.
  * THE MANIFEST MUST BE WRITTEN ON NO-OP RUNS. Steady state IS a no-op run, so a
    manifest that only regenerates when there's fresh data goes stale on exactly the
    schedule it serves, and every button vanishes on the first quiet day.
  * THE $FILES ALLOWLIST in update-odds.yml is explicit. A new data file that isn't
    in it gets generated and never committed. Green job, starved feature.
